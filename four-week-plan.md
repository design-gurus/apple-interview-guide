# A Four-Week Plan for the Apple Interview

Four weeks is enough time to prepare for an Apple loop if you study about ten hours each week. Week 1 covers the team and the coding patterns, week 2 covers code quality and your own projects, week 3 covers system design, and week 4 covers behavioral stories and a full practice loop. Each week ends with a finish condition, which is a test that tells you the week is complete.

## The plan in one table

| Week | Focus | Hours | Finish condition |
|---|---|---|---|
| 1 | Team research and coding patterns | 10 | 12 medium problems solved, each within 30 minutes |
| 2 | Code quality and domain depth | 10 | 5 one-page project summaries, each tested with 3 follow-up questions |
| 3 | System design | 10 | 3 designs spoken aloud in 45 minutes each |
| 4 | Behavioral stories and a practice loop | 10 | 6 stories written, and 1 full practice loop completed |

## Week 1: the team and the patterns

Each Apple team owns its loop, so begin with the team.

- Ask your recruiter how many rounds there are, what each covers, and which languages are expected.
- Read the job description and list every technology that it names.
- Study six patterns: sliding window, two pointers, hash maps, tree traversal, heaps, and binary search.
- Solve two problems from the [Question bank](question-bank.md) for each pattern.

Start with the lesson [Introduction to Sliding Window Pattern](https://www.designgurus.io/course-play/grokking-the-coding-interview/doc/introduction-to-sliding-window-pattern?utm_source=github&utm_medium=repo&utm_campaign=apple-interview-guide&utm_content=four-week-plan), then continue through the other five patterns.

**Finish condition:** you solve 12 medium problems, each within 30 minutes, and you can name the pattern before you write code.

## Week 2: code quality and domain depth

Apple interviewers are reported to grade code as a teammate would in a review. The domain round then tests your own projects.

- Solve 10 more problems, and write each one with real names and handled edge cases.
- After each problem, change one constraint and solve it again.
- Write one page on each of your five strongest projects: the problem, your decisions, and the measured result.
- For each project, prepare answers one level below your daily code, such as memory layout and locking.
- Practice the two reported questions: a thread-safe LRU cache and a hash map that grows.

**Finish condition:** another person asks three follow-up questions on each project, and you answer every one with a mechanism or an honest "I do not know".

## Week 3: system design

Skip this week if you are an entry-level candidate, and repeat week 1 with harder problems instead.

- Learn the round structure: requirements, high-level design, two deep parts, and weak points.
- Practice three designs: file sync, messaging across devices, and push notifications.
- For every design, answer three questions before scale. What data is encrypted and who holds the keys? What happens on an offline device? How do several devices sync?
- iOS candidates should replace two server designs with client designs. See [Roles](roles.md).

Use the lesson [Designing Dropbox](https://www.designgurus.io/course-play/grokking-the-system-design-interview/doc/designing-dropbox?utm_source=github&utm_medium=repo&utm_campaign=apple-interview-guide&utm_content=four-week-plan) for the file sync design.

**Finish condition:** you complete three designs aloud with a timer, and each one states privacy, offline behavior, and failure cases.

## Week 4: stories and a practice loop

- Write six stories in STAR form (Situation, Task, Action, Result) on craft, failure, disagreement, ambiguity, and influence.
- Write your "Why Apple?" answer and one product improvement that you can defend.
- Run one practice loop on one day: two coding sessions, one design session, and one project discussion.

**Finish condition:** you finish the practice loop, and each story names your own actions and a measured result.
